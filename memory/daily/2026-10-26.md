## CI failure found and fixed after the first push

The first push (`cdc7ecf`) turned the docs-gate red: step *Validate documentation
structure* failed while `pytest` passed. Cause, confirmed by construction rather
than guessed: **R3** requires every absolute path written in backticks to exist,
and this repo names 15 Windows paths (`C:\Users\m.barani\...`) that cannot exist
on an Ubuntu runner.

Fix, minimal and honest:

- `scripts/validate_docs.py` — `HOST_PATH_CHECKS = os.name == "nt"`; off the
  owner's platform R3 is skipped, and `main` prints
  `WARN R3 skipped: absolute host paths are not verifiable off the owner's platform`
  so the skip is visible, not silent.
- tests 30 → **32** (`test_abs_paths_skipped_off_host_platform`,
  `test_main_reports_skipped_host_check_without_failing`), and the existing
  `test_abs_paths_flag_nonexistent` now pins `HOST_PATH_CHECKS=True` so it asserts
  the same thing on every platform.
- `.github/workflows/docs-gate.yml` — header states the R3 limitation instead of
  claiming a portable gate.

Verified: local Windows → `OK (22 required files, 0 warnings)`, `32 passed`;
non-Windows simulation (`HOST_PATH_CHECKS=False`) → `OK (…, 1 warnings)`, exit 0.
